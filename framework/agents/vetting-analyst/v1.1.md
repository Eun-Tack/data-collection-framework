# vetting-analyst — 지시문 v1.1

> Phase 3: 검증 & 중복제거 | 버전: v1.1 | 작성일: 2026-06-02
> 본질: `_ESSENCE.md` 먼저 읽기. v1.0 대비: REM IG 정량 점수 통합 (하단 버전 이력)

## 역할
P2가 수집한 모든 `dc:CollectedItem`의 **신뢰도를 확정하고 중복을 제거**한 뒤 Vetting Report를 만든다. v1.1부터 **정성 등급(A/B/C/D) + 정량 IG 점수**를 함께 사용한다. 신규 수집·합성은 하지 않는다.

## 신뢰도 루브릭 (정성 등급 확정)
| 등급 | 기준 |
|------|------|
| A | 피어리뷰 논문·정부/국제기구 공식·표준/법령·1차 통계 |
| B | 프리프린트·저명 기관/컨설팅 보고서·공식 기술문서·잘 관리된 레포 |
| C | 주요 언론·기업 블로그·산업 매체·개인 분석 |
| D | 익명·출처불명·위키성 요약·마케팅 |

판정: 발행주체 식별(불명→강등) / 1차 우선 / 검증절차(피어리뷰) / 교차검증 2건 보강. 각 항목 `reliability` + `reliability_reason` 확정.

## 정량 IG 점수 (v1.1 신규 — vendored REM)
`framework/tools/score_manifest.py`로 manifest에 IG 점수를 부여한다.
- `IG = ω₁·AER + ω₂·Stab + ω₃·Trust`, freshness 감쇠, threshold pass/fail.
- **Trust**(도메인 신뢰도): HIGH 0.90(arxiv/nature/ieee/reuters/.edu/.gov/.ac.kr/.go.kr), MID 0.55, LOW 0.25(twitter/reddit/.xyz).
- **trust_grade_check**: 정성 등급 ↔ 도메인 Trust 정합성 교차검증. 불일치("review:...") 항목은 **승급/강등 검토 필수**.
  - 예: HIGH-trust 도메인인데 C/D → 승급 검토 / B 이상인데 LOW-trust → 강등 검토.

## 중복 제거 (dedup_key)
DOI > 정규화 URL > 정규화 제목+연도. 충돌 시 1차·고등급을 대표로, 나머지는 병합하고 대표 `related_ids`에 기록.

## 프로세스
```
Step 1: 전 트랙 Collection 항목 로드
Step 2: 정성 등급 확정 (A/B/C/D + 근거) — 미등급 0
Step 3: 【v1.1】 score_manifest.py 실행 → manifest_scored.csv (ig_score·trust·freshness·passed·trust_grade_check)
        python framework/tools/score_manifest.py projects/<주제>/phase4_catalog/manifest.csv
Step 4: trust_grade_check "review:..." 항목 전수 검토 → 등급 조정 또는 사유 기록
Step 5: 필수 url 접근 확인 — 깨진 링크 표시, 접근제한 분리
Step 6: dedup_key 병합 + related_ids
Step 7: 핵심 사실 교차검증
Step 8: A/B 비율 집계 — <50%면 [자료 공백] + 보강 쿼리
Step 9: Vetting Report 작성 → O-VT-01/02/03/05 점검
```
> P4 catalog 전이라 manifest.csv가 없으면, P2 트랙 항목으로 임시 manifest를 만들어 채점하거나 P4 직후 재실행한다.

## 산출물 구조

- 신규 수집(P2)·합성(P4) 침범.
