# catalog-synthesizer — 지시문 v1.1

> Phase 4: 카탈로그 & 합성 | 버전: v1.1 | 작성일: 2026-06-02
> 본질: `_ESSENCE.md` 먼저 읽기. v1.0 대비: 입력을 manifest_vetted.csv로, 최종 산출을 manifest.csv로 명확화.

## 역할
P3에서 검증된 `phase3_vet/manifest_vetted.csv`를 받아 **최종 카탈로그 + `phase4_catalog/manifest.csv` + 합성 요약**으로 통합한다. 신규 수집·등급 변경은 하지 않는다.

## 매니페스트 단계
- **입력**: `phase3_vet/manifest_vetted.csv` (등급 확정·중복 병합·IG 점수 포함).
- **출력**: `phase4_catalog/manifest.csv` (최종, 정규 14컬럼 + 선택 IG 컬럼 유지 가능).
> raw(P2) → vetted(P3) → **final(P4)** 단계 분리.

## 프로세스
```
Step 1: manifest_vetted.csv + Vetting Report + Collection Spec(성공기준) 로드
Step 2: dc:Catalog 본문 작성 (트랙별·등급별, 각 항목 메타+요점)
Step 3: 최종 manifest.csv 생성 (vetted에서 확정분만, 컬럼 순서 고정) — 본문 항목 수와 일치
Step 4: 합성 요약 — Top-N + 신뢰도/IG 분포 + 성공기준 충족 표 + 공백 + 다음 제안
Step 5: 게이트 자동 판정
        python framework/tools/validate_project.py projects/<주제>
        → errors=0 (provenance·컬럼·건수 일치 자동 확인)
```

## 매니페스트 CSV 컬럼 (정규, 고정)
```csv
id,track,title,authors,source_type,url,publisher,pub_date,retrieved_date,lang,reliability,reliability_reason,dedup_key,related_ids
```
(IG 통합 시 ig_score·trust·trust_tier·freshness·ig_passed 컬럼을 뒤에 유지 가능. `abstract`·`key_points`는 카탈로그 본문에.)

## 합성 요약 구조
```
## 1. 수집 요약 (총 n건 · 트랙·등급·IG 분포)
## 2. 핵심 자료 Top N (요점 3~5 + 인용)
## 3. 성공기준 충족 여부 (Collection Spec 대비)
## 4. 신뢰도·공백 노트
## 5. 다음 수집 제안
```
